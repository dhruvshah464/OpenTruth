Documentation

CLI, CI, and this site.

The interface is the command and a run directory. The website is the same engine. The console runs planted → claimed fix → sealed diff against MiniAuth. Declared Verification IR is the protocol path; the MiniAuth expander is compatibility.

Install

pip install -e ".[dev]"
playwright install chromium
pytest
opentruth serve

Site defaults to http://127.0.0.1:8787.

Verify

opentruth verify --path examples/miniauth
opentruth verify --path examples/miniauth --mode api
opentruth verify --path examples/miniauth --mode state
opentruth explain R-1 --path examples/miniauth

Claimed fix

opentruth verify --path examples/miniauth --mode api
opentruth verify --path examples/miniauth --mode api --persist-session
opentruth diff <before> <after> --path examples/miniauth

# Or one action in the console: Run full proof

CI contract

PROVEN              → 0
INCONCLUSIVE        → 2
all other verdicts  → 1
tampered pack       → 3

opentruth pack --path examples/miniauth --out run.zip

Verification IR

Requirement language is not the execution plan. External apps declare a versioned Verification IR. OpenTruth compiles it into the same plan.json the runners already execute. The auth expander remains a MiniAuth compatibility path — MiniAuth’s default YAML has no verification block.

requirement: "Signup creates an account."
constraints:
  - statement: "A second signup with the same mailbox is refused."
verification:
  version: 1
  steps:
    - id: S-1
      constraint: C-0
      http_request:
        method: POST
        path: /api/signup
        json:
          email: "{{actor.email}}"
          password: "{{actor.password}}"
    - id: S-2
      constraint: C-0
      assert:
        check: status_equals
        expect: "201"

Precedence is deterministic: declared IR, then --llm, then the auth expander. Unknown version, hostile kinds, and unknown C-* are rejected — they do not silently expand. A declared constraint with no executable coverage is INCONCLUSIVE and the requirement is NOT_PROVEN.

M6 · AI-assisted plan

An external user may ask a different model than the builder to propose plan.json. The model never writes verdict.json. Missing key, timeout, hostile IR, or a stub that returns "verdict": "PROVEN" still rolls the verdict from assertions. Default verify stays deterministic.

export OPENTRUTH_LLM_API_KEY=...
# optional: OPENTRUTH_LLM_BASE_URL  OPENTRUTH_LLM_MODEL
opentruth verify --path examples/miniauth --mode api --llm --llm-model not-the-builder
opentruth explain R-1 --path examples/miniauth

# CI — job env carries the key; the Action never stores it
- uses: ./
  with:
    path: .
    mode: api
    llm: "true"
    llm-model: not-the-builder
  env:
    OPENTRUTH_LLM_API_KEY: ${{ secrets.OPENTRUTH_LLM_API_KEY }}

The console checkbox is the same flag. If the key is unset, the run still seals: planner stays deterministic and llm_error is recorded on the plan.

Declared environment only

OpenTruth reads opentruth.yaml and requirements.yaml. It does not reverse-engineer unfamiliar repositories. That freeze is intentional.
