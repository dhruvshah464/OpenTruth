01 / Thesis

Verifier ≠ Builder.

The same agent that shipped the feature is not the entity that decides it works. OpenTruth never writes tests into the target repository. Plans and evidence live only under a hash-sealed run directory. PROVEN is not a log line.

  • PROVENEvery planned assertion for the requirement was observed to hold.
  • PARTIALLY_PROVENHappy path holds; at least one constraint fails — as MiniAuth does on session persist.
  • FAILEDThe required happy path was observed not to hold.
  • NOT_PROVENCoverage too thin, or a claimed change did not establish the requirement.
  • INCONCLUSIVECould not observe (app down, timeout). Never counted as pass or fail.
02 / Layers

Six proof layers. One graph.

Each milestone adds a kind of proof that writes into the same sealed namespaces: R-*, C-*, A-*, O-*, E-*. Nothing else is the product.

M1

Browser proof

Operate the UI in Chromium. Observable behavior becomes actions, observations, assertions.

M2

API proof

Direct HTTP: valid, invalid, unauthorized, state transitions. Same graph, kind: http.

M3

State proof

After the system claims signup succeeded, read durable storage. Invariants, not dashboards.

M4

Change proof

Two sealed runs. What improved, held, or regressed. Differential evidence cites both run IDs.

M5

Continuous

The CLI in CI. Exit code plus a packed sealed run. Still not a service.

M6

AI-assisted plan

An LLM may propose plan.json. It never writes verdict.json.

03 / Graph

04 / Product

The engine is running.

This site is not a marketplace. The console executes the real verifier against MiniAuth: planted bug, claimed fix, then a sealed diff. Default single proof is PARTIALLY_PROVEN. The full loop ends PROVEN on the delta.
