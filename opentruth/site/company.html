Laboratory

A verification lab,
not a SaaS backlog.

OpenTruth is an open verification protocol for independently establishing software requirements from executable evidence. Nearby slots — test generators, claim checkers, spec gates, formal methods — are occupied. The unoccupied gap is live operation of the product, with a walkable, hash-sealed graph. This website is a control surface for that engine, not a second verifier.

Position

Deep tech is the constraint set.

We optimize for defensible verdicts. Complex protocol; simple interface. The planner can change; the notebook machinery does not. If a change does not make PROVEN more defensible, it waits. The local console is the same verifier as the CLI, pointed at MiniAuth.

Independence

Separate from the builder

Evidence is never written into the repository the agent just edited.

Integrity

Tamper is visible

Rewrite any sealed file and the run is no longer evidence.

Refusal

INCONCLUSIVE is honest

Inability to observe is not a product failure and not a pass.

Laws

Eleven laws. Not slogans.

Implementation follows the protocol specification. These do not weaken so the product can look simpler.

  • 01Verifier ≠ Builder
  • 02Verdict ≠ model opinion
  • 03Evidence is inspectable
  • 04Evidence is integrity-protected
  • 05Failed verification ≠ software failure
  • 06Inconclusive ≠ proven
  • 07Requirements are explicit
  • 08Verdicts are reproducible
  • 09AI may propose; machinery decides
  • 10Every claim points to evidence
  • 11The planner can change; the notebook does not
  • —Apache-2.0 · local engine · no hosted scanner

What we will not become

Named so the lab stays an engine.

  • Automatic requirement discovery
  • Unfamiliar repository analysis
  • Multi-agent verification
  • Production observability dashboards
  • Verification marketplaces
  • Enterprise SaaS as the product
  • Hosted URL scanning
  • Running the builder’s tests as proof
